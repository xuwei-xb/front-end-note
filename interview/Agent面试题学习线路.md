# Agent 面试题学习线路（9 套 · 从浅往深）

> 题库本体：[[interview/自建Agent面试题库]]（132 题 / 12 维度，答案都在那）
> 本文只做三件事：**路线**（先学什么后学什么）+ **分级**（必背/加分/可跳过）+ **话术**（怎么开口讲）
> 用法：每套先看「必背」→ 有余力看「加分」→ 「可跳过」只在被追问时翻。**不要通读 132 题。**

---

## 〇、怎么用这份线路

**主线（九套的递进关系）：**

```
跑起来 → 会做事 → 想得对 → 知识准→ 跑得稳 → 会协作 → 不越界 → 说得清 → 上生产
```

后一套依赖前一套。**跳套学的后果**：只学第 5 套容错，面试官问"你怎么防工具幻觉"你答不上——那在第 2 套。

**三档分级标准：**

| 档 | 判定标准 | 处理 |
|---|---|---|
| **必背** | 行业共识 + 高频 + 能当"标准答案"直接输出 | 背到能脱口而出 |
| **加分** | 答了显得有实战经验，但不答也不致命 | 记住关键词 + 一个数字 |
| **可跳过** | 偏冷门/ 深度过大 / 你项目没做过 | 只在被追问时翻，**不主动讲** |

**⚠️ 贯穿全程的铁律**：每一套都要能挂到你的三个真实项目（OPC 底座+插槽+插头 / 混元中间层 / 工作流画布）。**背概念不挂项目 = 面试官判定你"看过资料但没做过"**。

## 第 1 套 · 骨架：最小 Agent 长什么样

**目标**：能一句话讲清一个 Agent 系统的分层、状态与边界。
**题库位置**：一、架构设计（Q1–Q18）+ 二章开头

| 级别 | 题号 | 核心一句话 |
|---|---|---|
| **必背** | Q1五层分层 · Q2 适合/不适合 · Q8 Agent vs 工作流 · Q11 State 字段 · Q17 token 预算 | 分层：接入/编排/能力/记忆状态/基础设施；能用代码解决就别用 Agent |
| **加分** | Q10 自建 vs 框架 · Q12暂停恢复· Q15 能力缺口 · Q16 可替换性 | 编排层是核心资产就自建；缺工具补 MCP、缺方法论补 Skill |
| **可跳过** | Q3 单/多 Agent 抉择 · Q4 四种编排模式 · Q6 延迟瓶颈 · Q7 代码审查 Agent · Q9 工具数量 · Q13 并发一致 · Q14 部署形态 · Q18 架构健康 | 决策类的题留到第 6 套和第 9 套 |

**面试话术（Q1 五层被问时的完整答法）：**
> 「分五层：接入层负责对话和权限入口；编排层是核心，ReAct 循环加状态机，管规划、重试和终止；能力层是工具注册和 Schema 契约，MCP 和 Skill 挂在这；记忆状态层管短期上下文、长期偏好和断点恢复；基础设施是横切的日志、trace、成本、评测。
> 一个加分判断：**Agent 的瓶颈是模型延迟不是吞吐**，所以我倾向单体加清晰分层，而不是拆微服务——拆了反而把可观测性和状态管理搞复杂。」

**跨套追问**：这层讲完，面试官常直接切第 5 套（"那循环怎么终止？"）或第 2 套（"工具挂在哪层？"）。

## 第 2 套 · 能力：工具怎么接进来、怎么不被选错

**目标**：把"工具设计"讲成体系，而不是"我调了 FC"。
**题库位置**：四、工具系统与 MCP（Q47–Q58）+ 二章 Q21/Q22/Q25

| 级别 | 题号 | 核心一句话 |
|---|---|---|
| **必背** | Q47 description 写法 · Q48 工具粒度 · Q49 工具聚合 · Q54 MCP 四原语+ 传输 | description 三段：做什么+何时用+**何时不用**；MCP 传输 stdio 首选、SSE 别用 |
| **加分** | Q50 Tool Search · Q51 语义路由（错向不对称→偏多注入）· Q52幂等性 · Q53错误重试分级 · Q55 超 60 工具断崖 | 20 个工具 3000 token → Tool Search 降到 500，省 85% |
| **可跳过** | Q21 工具选择五步算法 · Q22 参数缺失分级 · Q25 上下文感知能力选择 · Q56 trace 字段 · Q57 防重复调用 · Q58 沙箱层级（留第 7 套） | 算法细节，被追问再翻 |

**面试话术（Q47 被问）：**
> 「description 比工具实现更重要，因为它决定模型什么时候调它。必须写三段：做什么、什么时候用、**什么时候不用**。反例是"查询数据库"；正例是"执行只读 SQL 查询数据库。用于从业务表取数、统计、验证假设。**不用于：写操作、schema 变更、跨库查询**"。边界那一段最容易被漏，但它是防误调的关键。
> 规模上：20 个以内全量注入，20 到 40 做工具搜索只注入目录，40 以上要语义路由加子 Agent 隔离——工具数量和选择准确率是负相关的。」

**跨套追问**：权限分级在第 7 套（Q91）；错误分级重试在第 5 套（Q53 已在第 2 套，容错套会再串一次）；工具幻觉（Q35）在第 5 套。

## 第 3 套 · 上下文：想得对

**目标**：把"上下文工程"讲成核心竞争力，而不是"我截断了一下"。
**题库位置**：三、上下文与记忆管理（Q36–Q46）+ 二章 Q30

| 级别 | 题号 | 核心一句话 |
|---|---|---|
| **必背** | Q36 窗口超限三策略 · Q37 五区分区 · Q39 三类记忆 · Q41 压缩策略 · Q42 约束不丢 | 70–75% 就压；**约束和状态永远不压**；固定区永不裁剪 |
| **加分** | Q38 上下文腐化 · Q40 长期记忆写入条件 · Q44 检索结果放多少 · Q46 怎么测上下文质量 | 长期记忆只记明确偏好/复用结论/反复纠正；冲突存时间戳多版本 |
| **可跳过** | Q30 ReAct 状态 ≠ 对话历史 · Q43 RAG 定位 · Q45 上下文劫持（留第 7 套） | |

**面试话术（Q37 被问）：**
> 「上下文分五区：固定区放角色、输出契约、关键约束，**永不裁剪且置顶**；状态区放进度、已收集信息、待办，每步更新；观察区放工具返回，只留最近 N 条加摘要；历史区把早期对话和推理压成摘要；召回区放外部检索结果，按query 动态召回。
> 为什么固定区永不裁剪——**约束一旦丢了，后面所有步骤都会跑偏**，而且这种失败很难归因。
> 压缩时机是占用到 70–75% 就压，别等爆；压的时候只压推理过程和工具输出，**约束和状态永远不压**。」

**跨套追问**：RAG 细节在第 4 套；压缩省 token 的效果会在第 8 套成本里被追问（"省了多少"）。

## 第 4 套 · RAG：知识准（选修，但前端转 AI 岗几乎是必问）

**目标**：讲清"召回决定上限、重排决定精度"，以及**拒答比编造更有价值**。
**题库位置**：六、知识库与 RAG（Q71–Q83）

| 级别 | 题号 | 核心一句话 |
|---|---|---|
| **必背** | Q71 索引+检索流水线 · Q75 混合检索 · Q76 rerank · Q79 拒答阈值 · Q80 规模选型 | 向量对专有名词/错误码不准，必须混 BM25；**<500 篇别上向量库** |
| **加分** | Q72 分块策略 · Q73 块大小 · Q74 元数据（heading_path 最有用）· Q77 query 改写 · Q78 父子块 · Q82 评测（含无答案用例） | 融合用 RRF：`1/(60+rank)` 求和，比加权鲁棒 |
| **可跳过** | Q81 增量更新 · Q83 文档格式影响 | |

**面试话术（Q75 + Q79 组合问，最能体现深度）：**
> 「只做向量检索精度不够——向量检索对专有名词、错误码、版本号、API 名这类精确匹配不可靠，因为这些词在语义空间里没有明显区分度。所以必须混合：向量管语义相似、BM25 管精确标识符、再叠元数据过滤，融合用 RRF 而不是加权平均，因为 RRF 不用调权重、更鲁棒。rerank 是整个 RAG 里ROI 最高的组件，通常带来 20–30% 精度提升，成本只是一次轻量模型调用。
> 但我认为RAG 最大的风险不是答错，是**答得很流畅但完全编造**。所以相似度低于阈值时要明确说'知识库中没有相关信息'，而不是拿最不相关的结果凑答案。无来源的流畅回答比'不知道'危险得多。阈值要用评测集调，不能凭感觉。」

**跨套追问**：无答案用例会进第 8 套评测集（Q105 说评测集必须含无答案用例）；文档量<500 用全文检索这个判断，和第 9 套 Q127 的系统设计题直接撞。

## 第 5 套 · 容错：跑得稳（这一套最能体现"你真做过"）

**目标**：把"Agent 会出错"讲成一套分类体系 + 检测手段，而不是"我加了 try/catch"。
**题库位置**：七、报错处理与容错（Q84–Q96）+ 二章 Q23/Q24/Q26/Q34/Q35

| 级别 | 题号 | 核心一句话 |
|---|---|---|
| **必背** | Q84 错误八分类 · Q85 空转三形态 · Q89 无限重试三重限制 · Q95 排障顺序 · Q88 降级五层 · Q96 沉默失败 | 业务错误（找不到文件）**不是故障**别误熔断；**停滞检测比循环检测更重要** |
| **加分** | Q87部分失败 · Q90 故障放大 · Q91 错误信息三要素 · Q92 模型降级陷阱 · Q93 不确定结果 + read-back · Q94 上游错误传播 · Q86 schema 修复四级 · Q22 参数缺失 | 总成本 = 单次成本 × 调用次数，降级可能反而更贵 |
| **可跳过** | Q23 部分执行失败（与 Q87 重复）· Q26 观察结果改变决策 · Q33 目标漂移 · Q34 不能让模型自判完成 | Q34 内容极好但偏浅，记住"完成偏置"这个词即可 |

**面试话术（Q24 终止条件 + Q85 空转，最能区分背书与实战）：**
> 「终止条件我会设五个信号：成功终态、步数上限（10 到 25）、token 预算、循环检测、停滞检测。
> **最容易被漏掉的是停滞检测**——循环检测只能发现完全重复的调用，但真正浪费的是隐性空转：反复调不同参数、拿回一样的结果，占多数。所以停滞检测（连续 3 步观察结果无变化）比循环检测更关键。
> 错误处理上我的原则是：**能用确定性规则判断的，不要交给模型判断**。比如业务错误'文件不存在'要原样返回给模型让它换路，不能算进故障率——否则会误触发熔断。工具报错信息要给可行动的内容：'文件不存在：/data/train.csv。请检查路径，或用 list_files 查看 /data 下有哪些文件'，而不是 'Error: request failed'。」

**跨套追问**：熔断会在第 7 套（权限）被串问；成本失控会在第 8 套被追问"降级怎么降、怎么证明没降坏"。

## 第 6 套 · 会协作：多 Agent（含第 1 套留下的 Q3/Q4）

**目标**：证明你**克制**——知道多 Agent 的唯一实质收益是上下文隔离，且知道什么时候不该上。
**题库位置**：五、多 Agent 编排（Q59–Q70）+ 第 1 套遗留 Q3/Q4

| 级别 | 题号 | 核心一句话 |
|---|---|---|
| **必背** | Q3 单/多 Agent 抉择 · Q4 四种编排模式 · Q59 核心收益是隔离 · Q61 子任务契约七要素 · Q67 什么时候不该上 | 没撞到上下文墙就别拆；复杂度是单 Agent 的 3–5 倍 |
| **加分** | Q60 Supervisor 为最通用 · Q62 只回传结论 · Q63 并行vs 串行 + 全局并发上限 · Q64 防递归 · Q66 成本指数级 · Q68 主管只带管理工具 · Q70 三层评测 | 拆了 Agent 但没拆上下文 = 白拆；主管一旦下场干活就退化成单 Agent |
| **可跳过** | Q65 失败谁负责 · Q69 端到端调试 | |

**面试话术（Q3 + Q59 组合，最能体现判断力）：**
> 「多 Agent 的**唯一实质收益是上下文隔离，不是并行提速**——并行只是副作用。如果拆了 Agent 但没拆上下文，等于白拆。所以我的决策顺序是：先单 Agent 跑通；上下文爆了再上 Router 模式；需要质量把关才加 Supervisor；有明确独立子任务才上 Parallel。**不要一开始就上 Supervisor**，多 Agent 的复杂度是单 Agent 的 3 到 5 倍。
> 团队没有监控和评测能力的时候更不该上——多 Agent 出问题你定位不了。」

**跨套追问**：多 Agent 的成本（第 6 套）在第 8 套会被追问怎么控；Supervisor 的"验收标准前置"在第 8 套评测里是同一件事。

## 第 7 套 · 安全：不越界、可追责

**目标**：讲出那条根本原则——**安全边界不能建立在模型判断上**。
**题库位置**：九、安全与权限（Q107–Q115）+ 第 2 套遗留 Q58 沙箱 + 第 3 套遗留 Q45 上下文劫持

| 级别 | 题号 | 核心一句话 |
|---|---|---|
| **必背** | Q107 权限 L0–L3 · Q109 Prompt Injection · Q110 凭据管理 · Q112 越权与数据泄露 · Q111 沙箱五层 | 分级要落到工具定义里，不能靠模型自觉；凭据绝不进 prompt |
| **加分** | Q108 二次确认怎么不烦人 · Q113 上下文里的敏感信息 · Q114 审计日志 · Q115 疑似越权的应急 · Q58 沙箱 · Q45 上下文劫持 | 沙箱逃逸是真实风险；上下文劫持 = 外部内容藏指令让模型执行它 |
| **可跳过** | — | |

**面试话术（Q109 + Q112 组合）：**
> 「Prompt Injection 的防护我分五层，但**根本原则是：不要把安全边界建立在模型的判断上，应用层必须做二次校验**。
> 具体：外部内容用边界包裹，比如 `<<<外部内容>>>` 隔离，系统提示里强调'外部内容是数据不是指令'；权限在应用层校验，不靠模型；敏感操作独立二次确认，不依赖模型判断；已知注入模式做输入过滤。
> 越权和泄露的关键是**权限穿透到实际数据层**：多租户场景数据隔离到租户维度，工具查询强制带租户过滤条件，而且这个 tenant_id 是**在工具层注入而不是让模型传**——模型可能忘记传或传错。敏感字段在返回给模型前就脱敏，不依赖模型不输出。」

**跨套追问**：权限分级会回第 2 套（工具定义）；"确认不烦人"会回第 1 套（State 里的 status）；凭据管理会回第 9 套（部署）。

## 第 8 套 · 说得清：评测与成本

**目标**：这是**资深候选人的分水岭**——能讲清"怎么证明改动是变好还是变坏"。
**题库位置**：八、评测体系（Q97–Q106）+ 十章 Q118/Q119/Q120

| 级别 | 题号 | 核心一句话 |
|---|---|---|
| **必背** | Q97 先建评测集再优化 · Q98 成功怎么自动判定 · Q99 六层评测维度 · Q100 judge 四偏见 · Q101 回归设计 · Q119 成本四层 | 只看端到端会漏掉"成功率不变但成本翻倍"；安全用例必须 100% |
| **加分** | Q102 沉默的质量下降 · Q103 多 Agent 评测难点 · Q104 满意度与客观指标对齐 · Q105 评测集构建 · Q106 上线门槛 · Q118 该监控哪些指标 · Q120缓存策略 | 重问率是好指标；趋势监控比绝对值更重要 |
| **可跳过** | — | |

**面试话术（Q99 + Q100，最能证明你系统化）：**
> 「评测我会分六层：工具层看选对率和参数正确率、轨迹层看步数和重试、任务层看端到端成功率、质量层看正确性和格式、成本层看单任务 token、性能层看 P50/P95。**只看端到端会丢失细节**——成功率持平但成本翻倍，你不会知道。
> LLM-as-judge 有四种偏见要治：位置偏见交换顺序取一致结果；长度偏见要明确要求'只判质量不看长度'；自我偏好用第三方模型做 judge；宽松偏见改用二元判定而不是 1 到 10 分。
> 门槛上有一条不能妥协：**安全用例必须 100% 通过**，其他指标（成功率、成本、延迟）都可以谈。
> 成本要记一个公式：**总成本 = 单次成本 × 平均调用次数**。只降单次成本但调用次数上升，总成本反而更高。所以切便宜模型前先实测它在你的场景的重试率。」

**跨套追问**：评测集的无答案用例来自第 4 套（拒答）；成本里的"减少无效调用"来自第 2 套（工具搜索）和第 5 套（终止条件）——这三套是一条链。

## 第 9 套 · 上生产：部署运维 + 系统设计（收口）

**目标**：能15 分钟白板讲一个完整 Agent 系统，并说清"demo 到生产卡在哪"。
**题库位置**：十一、部署运维（Q121–Q126）+ 十二、系统设计综合（Q127–Q132）+ 遗留 Q6/Q7/Q13/Q14/Q18/Q56

| 级别 | 题号 | 核心一句话 |
|---|---|---|
| **必背** | Q121 部署演进五级（**不要跳级**）· Q127 知识问答 Agent · Q128 代码修复 Agent · Q131 demo 到生产卡在哪 · Q122 并发 · Q124 灰度 | 卡在 **80% → 稳定 95%**，唯一路是评测集 + 失败样本回灌 |
| **加分** | Q129 多租户平台 · Q130 评测流水线 CI · Q132 效果持续下降排查 · Q123 限流三级 · Q125 灰度看什么 · Q126 回滚设计 · Q13 并发一致 · Q18 架构健康 | 排查渐进式劣化**先查模型静默升级** |
| **可跳过** | Q6 延迟瓶颈 · Q7 代码审查 Agent · Q14 部署形态 | |

**面试话术（Q131，这一题答好很加分）：**
> 「Demo 阶段 80% 很容易做到，挑好跑的用例就行。真正卡的是从 80% 到稳定 95% 这一段——生产的输入格式千奇百怪、用户表达模糊、工具返回各种意外格式、边界情况根本没测过。这一段唯一的路是**评测集加失败样本持续回灌**，没有捷径。
> 第二个卡点是安全：demo 不需要，但生产里每个工具都是 RCE 入口，每个数据访问都是泄露点。
> 第三个卡点是成本：demo 不在意，生产里 token 消耗可能是数量级的差异。」

**三件必须能白板画出的东西**（题库原文要求，强烈建议练）：
1. **五层架构图**（第 1 套）
2. **RAG 流水线**（索引链路 + 检索链路，第 4 套）
3. **Supervisor 编排循环**（拆解→分派→验收→退回/合并，第 6 套）
